# 从 test.db 重新初始化正式环境

本流程在保存真实关键词库的那台机器运行。只读取源 `test.db` 的关键词，创建新的 `data/review.db`；旧 demo.db、原始报告和源 test.db 保留。新库不复制旧用户、登录凭据、审查结果或历史记录。它不是在每次启动时重置数据库。

源表四个 TEXT 字段 A/B/C/D 构成联合键，I 是关键词字符串，写入项目 keywords.payload 的 a/b/c/d/e。若关键词列实际叫 valve，也支持自动检测；其他列名用 --keyword-column 指定。联合键保持原字符串，不 trim，不丢前导零。NULL、非字符串、空白关键词、重复键、空表和多个候选表都会拒绝导入。多张匹配表用 --table 明确选择。

## 1. 准备

在项目根目录安装最新依赖。保留本机 backend/local_adapters 下的真实实现，文件不会从 GitHub 下载或被初始化脚本覆盖：

```powershell
.venv\Scripts\python -m pip install -r backend/requirements.lock.txt
```

将下面命令中的路径换成你的真实关键词库绝对路径。先预览，不写入：

```powershell
.venv\Scripts\python scripts/setup.py --source "D:\你的目录\test.db"
```

如果实际关键词列叫 valve，且需要指定表：

```powershell
.venv\Scripts\python scripts/setup.py --source "D:\你的目录\test.db" --table "你的表名" --keyword-column valve
```

默认源文件是项目根目录的 test.db，不会读取 data/tests/test.db（后者是自动化测试专用）。

## 2. 创建正式数据库

先停服务，再执行初始化。把“你的内网用户名”换成登录接口返回的稳定用户名，该账号首次登录时会成为管理员：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/manage.ps1 -Action stop
.venv\Scripts\python scripts/setup.py --source "D:\你的目录\test.db" --admin-user "你的内网用户名" --apply
```

如果预览用了 --table 或 --keyword-column，正式命令也带上相同参数。脚本拒绝覆盖已有 review.db；若需另一份新库，用 --target 指定新的文件路径。不要直接删除或覆盖已有业务库。

脚本会备份已有 .env 到 data/config_backups，并修改这些配置：

```dotenv
APP_MODE=production
DATABASE_URL=sqlite:///D:/Projects/ai_review_unit_test/data/review.db
DATA_DIR=D:/Projects/ai_review_unit_test/data/review_files
LOCAL_AUTH_MODULE=local_adapters.login_adapter
LOCAL_REVIEW_MODULE=local_adapters.review_rules
BOOTSTRAP_ADMINS=你的内网用户名
```

路径按脚本所在项目实际生成。已有 SECRET_KEY、MODEL、APPLY_TOKEN 及其他接入配置保留，移除 DEMO_PASSWORD。没有 .env 时生成正式配置和随机 SECRET_KEY，不会创建 demo/admin 演示账号。首次导入是关键词初始版本，不生成旧审查历史。

## 3. 核对接入后启动

在 .env 中核对 MODEL、APPLY_TOKEN 和 ATTACHMENT_HOSTS。登录、图片下载及 review_item 必须是你本地已实现的版本；占位实现不能用于真实登录或审查。review_item 使用最新七参数接口。正式模式不回退到演示鉴权或假审查结论。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/manage.ps1 -Action rebuild
```

启动后页面显示“正式环境”，使用实际内网账号登录，检查关键词列表及一份真实报告。以后直接运行 start.cmd，不再运行初始化命令。Linux 使用 .venv/bin/python，按部署文档启动 API 和 Worker。

正式模式现支持 SQLite 和 PostgreSQL；本流程按你的要求使用 review.db。SQLite 使用单个 Worker；多人并发性能仍需在实际部署机器验证，后续可迁移到 PostgreSQL。

.env、源 test.db、新 review.db、本地适配目录和所有实际报告均被 Git 忽略，不上传仓库。
