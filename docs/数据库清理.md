# 历史与数据库空间

网页选中自己上传的报告后，点击“清除历史”。确认后删除该报告、原始 Excel、所有审查批次、结果和备注，无法撤销；保留用户、关键词、关键词审批和简要操作记录。运行中、排队中、暂停中的审查不能清除。管理员也不能清除他人的报告。

新版本不再保存登录、每项审查、备注修改、暂停和继续的操作日志；保留上传、审查发起与完成、下载、关键词变更及审批、账号权限和历史清除记录。关键词快照仍保存在审查批次中，审查发起日志不再重复保存整份快照。审查结果本身仍保留，便于展示和导出。

旧日志不会自动删除。先在项目根目录预览：

```powershell
.venv\Scripts\python scripts/cleanup_db.py
```

SQLite 删除记录后会保留空闲页供后续复用，文件通常不会马上缩小。需要清理旧日志并收回空间时，先停止 API 和 Worker，再执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/manage.ps1 -Action stop
.venv\Scripts\python scripts/cleanup_db.py --apply --vacuum
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/manage.ps1 -Action start
```

脚本先创建同目录时间戳 SQLite 备份，再清理旧版冗余日志、移除日志中的重复关键词快照，最后压缩。它不会删除报告、审查结果、用户、关键词或审批记录。备份仍占空间，核验成功后自行保留或转移。请确保有足够磁盘空间供备份及压缩使用。脚本仅支持 SQLite 的实际清理和压缩；PostgreSQL 需要使用其备份和维护工具。

## 重置所有报告及审查历史，保留关键词

此操作影响全部用户。保留用户、关键词、关键词审批及其操作记录；删除所有报告、解析项、审查批次、结果、备注、对应原始 Excel 和报告/审查操作记录。审批中关联的结果会解除关联，审批记录本身保留。原始 Excel 不在 SQLite 备份中，需要时先单独备份上传文件。

在项目根目录先预览（不修改数据库）：

```powershell
.venv\Scripts\python scripts/cleanup_db.py --reset-history
```

确定要重置时，停止 API 和 Worker，再运行下面的命令。脚本先自动备份 SQLite，再执行事务删除，最后压缩：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/manage.ps1 -Action stop
.venv\Scripts\python scripts/cleanup_db.py --reset-history --apply --vacuum
# 上一步成功后再启动；失败则先查看错误。
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/manage.ps1 -Action start
```

不要直接删除 demo.db，否则用户、关键词和审批记录也会丢失。脚本读取 `.env` 中的 DATABASE_URL 和 DATA_DIR，执行前核对它们指向要重置的本机数据。
